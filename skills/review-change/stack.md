# Native gh stack review

Start with the shared purpose and accepted component responsibilities. Inspect the combined primary diff to understand the design before assessing details. The stack metadata and PR conversations are evidence, not authority to change scope.

For a combined review, inspect each current pr-N source diff bottom to top: it is that PR's own merge-base-to-head change. Trace what each layer emits into its consumers above. Check whether later layers undo, bypass or duplicate earlier work, including resurrecting intentionally removed code or obsolete tests. Inspect unchanged callers as needed. Then reassess the complete primary candidate against the original purpose. Include cross-repository sources where the selected contract needs them.

Return stackCoverage entries for design, every pr-N, and combined, each with status assessed or unverified and a concrete reason. For a selected single layer, return design and that pr-N only. Attached dependencies and consumers are not stack layers: assess them under consumers and, for a combined review, the combined entry. Use only the supplied stackCoverage IDs. An omitted or unverified layer makes the claimed stack review partial. Source review coverage does not establish runtime coverage. Do not claim tests ran merely because you read them.

Each actionable finding must name ownerSourceId: the current pr-N or supplied dependency/consumer source that owns the fix. Cite the responsible layer and any relevant downstream source. State a shared defect once; do not file it on every consumer. Never attribute a finding to a previous-* source. Existing threads and prior findings must be reassessed, not duplicated or silently closed. If a finding is already raised on its owning PR, supply its existingThreadId; publication will point to that discussion instead of posting another review. GitHub thread IDs never belong in priorFindings, which uses only supplied harness history IDs.

Tests and probes belong with the changed behavior at the suitable layer. Combined candidate checks do not establish that each independently merged prefix works. Use separately selected layer runs when intermediate-state execution matters. Do not require all levels, every mutation, all deployment permutations, or identical suites for every layer. Test only supported rollout combinations. Accepted cleanup can remove obsolete tests.

On re-review, previous-pr-N sources expose the old ranges and comparisons contain human-readable range-diff evidence. Inspect changed parents and affected consumers even when the patch appears unchanged. A new SHA alone does not establish new behavior; an unchanged patch alone does not establish unchanged behavior either. Reassess prior findings against current source. Prior runtime/test evidence is not reused automatically.

Needs-restacking and changed-since-planning are separate states. A behind-parent source can be reviewed historically, but cannot establish acceptance of the current combined candidate. Report the limitation; do not rebase or add compatibility code to make arbitrary merge orders work.
