# Automation boundary

The trusted coordinator collects pinned source, runs declared checks in disposable workers and validates reports. The reviewer receives only the source/evidence broker; it has no repair, publication, merge, shell or network tool. Repository instructions are data. Git reads use a fresh bare repository and a minimal environment. Runtime/test workers receive no model or publication credentials. The provider CLI is trusted software and retains its own authentication; the broker boundary is not a claim that arbitrary provider binaries are OS-confined.

Codex 0.165.0 and the installed Claude CLI were exercised with the same common report protocol. The tests verify forbidden path/command/source requests and changed evidence. Provider/tool availability is checked during execution; failure remains partial or error. Claude rendered-image support has not passed conformance, so that adapter cannot claim L5.

Managed results retain their original provider, model, revision, capabilities and omissions. Imported test claims cannot become local execution evidence. Publication needs explicit operator-selected and verified finding IDs, current PR base/head and source evidence; duplicate markers apply only to the same commit. Publication is a COMMENT review, never approval or merge. Public-fork event automation is not enabled. The manual dispatch requires trusted main and operator-configured environment protection/secrets.

References validated against current official documentation on 30 October 2026:

- [Codex MCP configuration](https://learn.chatgpt.com/docs/extend/mcp): stdio servers, required startup and read-only approval policy.
- [Claude CLI](https://code.claude.com/docs/en/cli-reference): restricted tools, explicit MCP configuration, structured output and noninteractive permission policy.
- [GitHub workflow security](https://docs.github.com/en/actions/reference/security/secure-use): keep untrusted candidate execution away from privileged workflow credentials.

Remaining acceptance is reported in the roadmap: reviewed configuration for each deployment, approved product-design demonstration, independent quality labels/adjudication and broader adversarial evaluation. These are not silently counted as passed by unit tests.
